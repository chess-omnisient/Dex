# Omnisient — Claude Working Instructions

## About Omnisient

Omnisient makes data collaboration safe and private so businesses can innovate, unlock new revenue, and reach more customers — while protecting what matters most: consumer trust.

We serve companies in retail, telecommunications, and healthcare that own high-value data. Our platform enables trusted brands to monetize their data through expert matchmaking with non-traditional partners, and gives banks, insurers, and bureaus rapid, safe access to high-value alternative data sources.

**Mission:** Use data for good — from financial inclusion to healthcare breakthroughs.

## Writing Style

### Tone
- Clear and outcome-focused
- Active voice — never passive
- Concise: 2-sentence maximum per paragraph for most content
- Use "we" not "I" in all documentation
- Avoid jargon unless it's standard PM terminology

### Formatting
- Always use Oxford commas
- Use bullet points for lists (numbered only when sequence matters)
- Bold **key terms** on first use
- Every PRD must include a "User Stories and Acceptance Criteria" section

## Immutable Rules

### ALWAYS
- Include acceptance criteria in every user story
- Use active voice in product documentation
- Back PRDs with user research

### NEVER
- Write PRDs without user research backing
- Skip acceptance criteria in user stories
- Use passive voice in product documentation

## User Story Format

Use this structure for all user stories:

```
**As a** [persona],
**I want** [action/feature],
**So that** [outcome/value].

**Acceptance Criteria:**
- [ ] [Criterion 1]
- [ ] [Criterion 2]
- [ ] [Criterion 3]
```
