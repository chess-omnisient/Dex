A project is a workspace for data analysis and visualization. Each project contains the datasets, reports, and selections needed to run a specific type of analysis. Projects are created from templates that define what type of analysis is performed and what data is required.

Project types

Projects are created from templates. The available templates depend on your organization's subscriptions agreements.

Setting Up a Project

Project Creation

Projects are created from the Projects section of the platform, accessible via the side navigation.

Two ways to start:

  1. Side navigation shortcut: Click the + icon next to "Project Workspace" navigation link in the side navigation. This opens the project creation screen directly.

  2. Projects screen: Click the "Projects Dashboard" navigation link to open the full project table, then select Create Project in the top right corner. This opens the same project creation screen.

Selecting a Dataset

To be matched, two datasets need at least one common PII field.

When you pick a dataset, Omnisient checks for this automatically. If there's no common field, an inline error blocks the choice.

To resolve it, you can either:

  • Simplest fix: choose a different dataset that already shares a common PII field.

  • If your own dataset is missing the field, re-upload it with the required common field.

  • If the partner's shared dataset is missing the field, ask your partner to reshare it with the field needed to match, as only they can change what their dataset exposes.

Matching types

When creating a project, you choose how records are matched between datasets. The match type you select influences how matching is performed in the project.

Match type

How it works

When to use

Best Match (Recommended)

The platform automatically matches across multiple PII fields to find the strongest possible match.

Default. Use when you want the highest match rate.

Choose Own Match Field

Matching is performed on a single PII field you select manually (e.g., ID Number).

Use when you want to match on one specific, known identifier.

Best Match Match Fields

Best Match evaluates the available PII fields on a dataset and gives its highest matching confidence to a set of identifiers, the primary match field for most projects is South African ID Number.

💡 Overlap and Custom projects support an expanded set of match fields:

  1. Social Security Number as National ID

  2. Passport Number

  3. Full Credit Card Number

Project Lifecycle

Project Approvals

Some project types require approval before processing begins. The approver depends on the project type. This may be the partner dataset owner, a subscription owner, or an internal review. In all cases, Omnisient can also action approvals.

Once submitted, your project status changes to "Awaiting Approval". You will receive a notification when the project is approved or rejected.

Project Status

Status

What it means

Awaiting Approval

The project has been submitted and is pending approval from the partner dataset owner, subscription owner, or an internal review.

Processing

The project has been approved and analysis is running.

Active

The project is ready to use.

Failed

Processing did not complete successfully.

Rejected

The project was not approved. A rejection reason is included in the notification.

Locked

The project's subscription or a dataset share it depends on has expired, been deactivated, or been revoked. The project cannot be used until every blocking issue is resolved. See Project Locking below for details.

Project locking

A project becomes locked when its subscription or a dataset share it depends on expires, is deactivated, is revoked, or has a start date moved into the future. Opening a locked project shows every reason it's currently locked, each as its own card in a stack. Every reason must be resolved before the project unlocks.

Each card shows the fields relevant to its type:

Issue type

Fields shown

Dataset share expired

Dataset name, expiry date, dataset owner

Dataset share deactivated

Dataset name, deactivation date, dataset owner

Subscription expired, starting in the future, or revoked

Subscription type

You can't resolve any of these yourself. Select Contact support to open a support chat pre-populated with every reason currently listed, so you only have to describe the problem once. If the only card shown is "Project unlocking failed," Contact support opens a chat about that specific failure instead.

Effective Expiry Date

To help you plan ahead, the Projects table shows an Expiry Date column so you can see when each project will lock without opening it. The date shown is the earlier of two scheduled dates:

  • the subscription end date for the project type,

  • or the dataset share expiry date (the earliest one, if a project draws on more than one dataset share).

Deactivation and revocation aren't scheduled, so they don't appear in this column. You'll only see them once they've happened, on the locked project screen itself.

Working in a Project

Refreshing a project

Refreshable projects can be re-run against updated data without creating a new project. The project code, structure, and all user-created work are retained with only the underlying analysis is updated.

To trigger a refresh, open the project and click Refresh Project from the refresh widget.

The project enters Processing status while the refresh runs. You receive an email notification when it is ready.

Owners and Read and Write users can trigger a refresh.

What is preserved

The following are retained throughout a refresh:

  • Custom datasets: any datasets you have created within the project remain intact

  • Saved queries: all saved queries in SQLPad remain linked to the project

  • SQLPad and Jupyter work: code, notebooks, are not affected

  • Selections: all selections remain linked to the project

  • PowerBI report: the connected report continues to function and reflects the refreshed data once processing is complete

If a refresh fails

If a refresh does not complete successfully, the project automatically reverts to the last active version and returns to a ready state. Your previous results and all user-created work remain accessible. The project does not enter a Failed status as a result of an unsuccessful refresh.

Analytical tools

SQLPad and Jupyter Notebook are available for data analysis within projects. Access may be restricted depending on your project type. Copy and paste is restricted in both tools.
