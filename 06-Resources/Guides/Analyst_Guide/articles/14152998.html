Overview

SQLPad is the SQL query editor available from Own Data Prep or inside your Omnisient project. This guide covers the most common errors users encounter and how to resolve them.

💡 SQLPad connects directly to your project's data environment. Most errors are caused by connection timeouts, write-back errors, or session issues - not problems with your data.

How to Access SQLPad

SQLPad is accessed from Own Data Prep or inside a project:

  1. Open your project from the Projects Dashboard

  2. In the project detail view, locate the Open with option

  3. Select SQLPad from the menu

⚠️ If you don't see the Open with option, scroll down on the project detail page — it may be below the fold. Your project must also be in a Ready state before SQLPad can be opened.

Navigating Back to Your Project

To return to your project from SQLPad, use the breadcrumb navigation at the top of the page. Click your project name in the breadcrumb trail to go back to the project detail view.

Common Errors and Fixes

1. Error When Writing a Dataframe to SQL

What you see: You run a write operation from Jupyter (e.g., writing a dataframe back to a SQL table) and receive an error.

First thing to check: Confirm the exact source table name - even a small difference will cause this error. Cross-check the table name against what appears in your dataset on the Datasets page.

If the table name is correct and the error persists, contact support with:

  • Your project name

  • The source table name you were writing to

  • The full error message

2. SQL Server Timeouts

What you see: Queries run for a long time and then time out, or SQLPad becomes unresponsive.

Steps to fix:

  1. Add a LIMIT clause to reduce your result set — start with LIMIT 1000

  2. Avoid SELECT * on large tables — select only the columns you need

  3. Add filters to narrow the dataset before running aggregations

  4. If timeouts persist on simple queries, contact support — the issue may be server-side

💡 If timeouts started suddenly and your query hasn't changed, log a support ticket so the team can check server status.

3. SQLPad Fails to Load / Connection Error

What you see: SQLPad opens but shows a connection error, blank screen, or spins indefinitely.

Steps to fix:

  1. Refresh the page and try opening SQLPad again

  2. Check your project status - if it shows Processing or Failed, SQLPad will not connect until the project is ready

  3. Log out and log back in to refresh your session

  4. Check with your IT team that all required URLs and IP ranges are whitelisted and are not being blocked by your firewall. View Firewall Access Required for more details.

4. Query Returns No Results

What you see: Query runs successfully but returns 0 rows.

Steps to fix:

  1. Remove all filters and run SELECT COUNT(*) FROM [table_name] to confirm the table has data

  2. Check that your project is using the correct dataset version - if the dataset was re-uploaded, you may be querying an older version

  3. Check for date filters in your query - the data range may not match what is in the dataset

Still Stuck

Contact support with the following information - this helps the team diagnose faster:

  • Your project name

  • The full error message (screenshot if possible)

  • The query or operation you were running

  • The table name you were querying or writing to
