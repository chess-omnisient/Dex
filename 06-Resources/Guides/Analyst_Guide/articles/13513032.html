When you mark a column as PII, Omnisient ensures it is anonymized and tokenized before upload, so your sensitive data is protected from the start. We use SMPC (Secure Multi-Party Computation) to keep these fields private while still enabling secure linking and collaboration across datasets. This approach helps support compliance with regulations such as POPIA, GDPR, and UAE data protection laws.

Social Security Number

An SSN consists of 9 digits, commonly displayed in the following format:

AAA-GG-SSSS
Example: 123-45-6789

Section

Description

AAA

Area Number (first 3 digits). Historically linked to geography, but no longer reflects location.

GG

Group Number (next 2 digits). Used for administrative sequencing.

SSSS

Serial Number (last 4 digits). Sequential within each group.

Your validation checks

Validation area

What we check

Examples of invalid and valid formats

Total length

SSN must contain exactly 9 digits (excluding optional dashes).

123-45-6789 and 123456789 are valid formats

Allowed characters

Only numeric characters are allowed (dashes are optional).

Letters or special characters are invalid

Area number (AAA)

Must be between 001–899, excluding 666.

000, 666, 900–999 is invalid

Group number (GG)

Must be between 01–99.

00 is always invalid

Serial number (SSSS)

Must be between 0001–9999.

0000 is always invalid

Zeroed sections

No section may be entirely zero.

All the following is invalid:

000-12-3456

123-00-4567

123-45-0000

All zeros

SSN cannot be all zeros.

000-00-0000

Restricted / example ranges

Known placeholder or example values are rejected.

Repeating or sequential digits is invalid:

123-45-6789

111-11-1111

Structural validity

SSN must follow the AAA-GG-SSSS structure.

Incorrect length or malformed values are invalid

Post-2002 CIPC Format Validation

Expected Pattern

YYYY/NNNNNN/NN

  • YYYY = year (2008 → current year)

  • NNNNNN = exactly 6 digits

  • NN = 2-digit entity type (e.g., 07 = Private Company)

Your validation checks

  • Regex must match the pattern

  • First 4 characters must be numeric (year)

  • Year must be no later than the current year

  • Input must contain exactly two slashes

  • All other characters must be digits

Old / Regional Format Validation

Expected Pattern

XYYYY/NNNNNN

  • X = a single alphabetic region code

  • YYYY = year (no later than the current year)

  • NNNNNN = 6 digits

Your validation checks

  • Regex must match the old/regional pattern

  • First character must be a letter

  • Next 4 must form a valid year

  • Input must contain one slash

  • All remaining characters (after the first letter) must be digits or a slash

If a record does not conform to either format, it will be flagged during the transformation step for further review.
